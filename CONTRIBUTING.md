# Contributing to Supavise

Thank you for helping. Bug reports, ideas and pull requests are all welcome.

## Before you open a pull request

- For a large change, open an issue first so we can agree on the approach.
- [docs/development.md](docs/development.md) explains how to build and test. [docs/design.md](docs/design.md) is the contract the code follows.
- Run `make fmt` and `make test` before you push.

## Contributor License Agreement

Supavise is licensed under [Apache-2.0](LICENSE). To accept a pull request, we need you to sign the [Contributor License Agreement](CLA.md) once. You keep the copyright in your work. The agreement lets the maintainer distribute it, including under other licenses.

When you open your first pull request, a bot comments with the link and the exact sentence to reply with. Post that sentence as a comment on the pull request, and the check turns green. If the check does not update, comment `recheck`.

If you contribute as part of your job, make sure your employer allows it. Section 4 of the agreement covers this.

## Reporting a security problem

Do not open a public issue. Use [GitHub's private vulnerability reporting](https://github.com/supavise/supavise/security/advisories/new).
